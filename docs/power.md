# 电源按钮（睡眠 / 关机）、远程唤醒（WOL）

> 2026-09-15 改版：**主路从「关机」换成了「睡眠(S3)」** —— 原来那套
> 「换成 ExitWindowsEx 就能不要 PIN」的结论**已被实测证伪**，见第一节。

## 一、为什么是睡眠，不是关机

```
手机点「睡眠」→ 确认框 → POST /api/sleep → sleep_pc()

> 那个确认框是**页面自己画的 `#ask` 弹层**，不是原生 `confirm()`。
> 2026-09-20 就是因为用了原生 confirm，手机浏览器把它屏蔽掉、静默返回 false，
> 用户看到的现像是「睡眠按钮点了没反应」。**别再换回原生 confirm** ——
> 完整事故经过和受害按钮清单在 `ui.md` 第〇节。
   → RT.unload("睡前卸载（S3 会让 CUDA 上下文失效）")   ← 见下面要点 2
   → SetSuspendState(0, 0, 0)                          ← 进 S3
```

**这台机器上任何真正的关机都必然停在登录界面**，跟怎么发起无关。而管理器的自启挂在
**用户登录**上（启动文件夹）→ 关机之后没人输 PIN，8090/8091 就永远起不来。
所以远程要能用，出路不是「换个姿势关机」，而是**别关机**：S3 把会话和进程原样留在内存里，
唤醒后管理器还在、不需要任何人登录；而且 S3 正是 WOL / WoWLAN 官方支持的状态
（关机态 S5 用 WiFi 是唤不醒的）。

### ⚠ v0.2.4：旧结论已被证伪，别再照着改回去

v0.2.3 曾把关机从 `shutdown /s` 换成 `ExitWindowsEx(EWX_POWEROFF)`，理由是
「开始菜单关机后会自动登录、`shutdown /s` 不会」。**实测把这条推翻了**：

| 证据 | 实测值 |
|---|---|
| Kernel-Power 109 的 Action | 开始菜单 = **6**（PowerActionShutdownOff）；管理器改用 EWX_POWEROFF 之后**也是 6**（09-15 21:40:58 / 21:46:46） |
| 「开机→会话建立」 | 开始菜单后 **27 秒**；EWX_POWEROFF 后 **34 秒** —— 本来就在同一档 |
| 那 76s / 138s 是怎么来的 | **人当时不在**、等人来输 PIN 的时间，不是关机方式的差别 |
| Winlogon 键 | **没有** `AutoAdminLogon` / `DefaultUserName` / `DefaultPassword` —— 这台机器从来没配过自动登录，「开始菜单关机后会自动登录」这个前提本身不存在 |

（另：快速启动是关的 —— `HiberbootEnabled=0` 且系统策略禁用 → 两条路都是真冷启动，
没有 hybrid shutdown 那回事。`whoami` 账户是空密码，但空密码照样要人点一下。）

三个实现要点（前两条的理由也写在 `model_manager.py` 的 `sleep_pc()` 上面那段注释里）：

1. **`SetSuspendState(FALSE, FALSE, FALSE)`，三个参数都必须是 FALSE。**
   `rundll32 powrprof.dll,SetSuspendState 0,1,0` 有名的「说要睡眠结果休眠了」，
   毛病不在 API：**rundll32 把 `"0"` 当字符串指针传进去，非 NULL 就是 TRUE**，
   于是三个参数全变 TRUE → 走休眠。自己用 ctypes 传真 BOOLEAN 就没这个问题。
   本机 `powercfg /a`：S3 可用、休眠可用、**混合睡眠不受支持**（虚拟机监控程序挡的）→ FALSE 就是干净的 S3。
2. **睡前必须先卸模型。** S3 会把 GPU 一起断电，唤醒后 CUDA 上下文一定失效；留着一个
   上下文已死的 llama-server 比卸干净更糟 —— 它多半是**卡住**而不是干脆报错，管理器还以为
   模型在、不会再重载，用户看到的就是「唤醒了但聊不了」。卸掉之后唤醒后第一条请求按需重载（10~15 秒）。
3. **先 `send_json` 再起睡眠线程**（顺序反了手机那边连接先断、只看得到「请求失败」，
   用户会以为没睡成再点一次）；并且**页面点了之后必须停轮询**（`SHUTTING` 闸门 + `clearInterval`）。
   不停的话 1.5 秒一次的 `tick()` 会连不上，把页面刷成「连接不上管理器」+ 一屏排查建议。

**「完全关机」还留着**（灰色按钮 → `/api/shutdown`），但它是**备选**：只用于确实要断电的
场合（比如搬机器）。走 `ExitWindowsEx(EWX_POWEROFF)`，失败兜底 `shutdown /s`。

### ⚠ v0.3.03：关机是**两步**的 —— 因为不加强制根本关不掉（2026-09-21 实测）

用户报「关机键坏了」。查事件日志，**根因和「PIN」那套完全无关**：

| 时间 | 事件 | 说明 |
|---|---|---|
| 09-21 01:49:12 | 1074 `pythonw.exe`（计划的） | 关机请求发出去了 |
| 09-21 **之后什么都没有** | — | 既没有 winlogon 的 1074，也没有 6006 / 109 → **卡在半路** |
| 06:11:36 | 同上，又一次 | 还是卡住 |
| 09-15 21:40:36 → :50 → :54 → :58 | 1074 → 1074(winlogon) → 6006 → 109 | 那次**真的关掉了**，这几条是齐的 |

**卡在哪**：Windows 收到关机请求后会挨个问程序能不能关。**有程序调用过
`ShutdownBlockReasonCreate()` 的话，系统会停在「这些应用阻止关机」那一页等人点
「仍要关机」** —— 而「完全关机」这功能存在的意义恰恰是人**不在**机器前。
本机注册这条的是 **Cherry Studio**，原因串是 `Cherry Studio is finishing background work`
（用 `ShutdownBlockReasonQuery()` 逐个窗口问出来的，探测代码在
`model_manager.py` 的 `shutdown_blockers()`）。

**所以改成两步**（用户 2026-09-21 选的方案）：

```
点「完全关机」→ 确认「要关机吗」
  → POST /api/shutdown {}          ← 不带 force：服务端**只探测，不关机**
      ├ 没有阻断者 → 直接关（不多问一遍）
      └ 有阻断者   → 返回 {ok:false, blocked:true, blockers:[{pid,name,reason}]}
                     → 弹第二层，把「谁挡着 + 原因串」原样摊出来
                     → 点「强制关机」→ POST /api/shutdown {"force":true}
```

`force` 才让 `ExitWindowsEx` 并上 **`EWX_FORCE`**（兜底的 `shutdown /s` 对应加 `/f`）。
`_power_off_like_start_menu()` 的**默认值仍然是 False** —— 别改成 True，
那等于绕过了用户那道确认。名字和原因串**不翻译**，系统给什么显示什么。

**已知代价（要接受）**：睡眠期间**断电 = 会话全丢** → 下次还是冷启动 + 要人输 PIN。
真怕这个就改用休眠(S4)，但每次睡/醒要几十秒读写 hiberfil，目前没做。

## 二、为什么没有「唤醒」按钮

两个各自独立、都绕不过去的原因，**别再试了**：

1. **管理器跑在这台要被睡/关掉的机器上**：一睡 8090 就没了，按钮恰恰在最需要它的时候打不开；
   而且浏览器 JS 发不出 WOL 的 UDP 广播。唤醒只能由**手机上的独立工具**做。
2. **关机态（S5）网卡不解码幻数据包**（微软口径：WOL 只在 S3/S4 受支持，含快速启动的 S5 也不行）。
   —— 这也正是把主路改成 S3 的原因：**S3 是唤醒有官方支持的那个态。**

## 三、唤醒侧：现状 + 要跑的命令

`powercfg /devicequery wake_armed`（2026-09-15 实测）里**只有** I225-V 网卡和键鼠：

| 设备 | 状态 | 能不能唤醒 |
|---|---|---|
| **Intel I225-V 有线口** | **已在 wake_armed**，驱动侧「唤醒魔包 / 唤醒模式匹配 / S5 魔包唤醒」全开 | 能 —— 但**网线没插**，且插上可能要改 BIOS |
| **Intel AX210 WiFi** | WoWLAN 相关的项都开着，**但不在 wake_armed 里** | 现在不能；补一条命令就能进 |
| 键鼠 | 在 wake_armed 里 | 只能人按 |

**走 WiFi 唤醒要跑的一次性命令（需管理员）**：

```
powercfg /deviceenablewake "Intel(R) Wi-Fi 6E AX210 160MHz"
```

跑完 `powercfg /devicequery wake_armed` 里应该能看到 AX210。**只能用在 S3/S4**
（S5 关机态 WiFi 唤不醒），所以跟「睡眠」主路正好配套。

**发包**：手机 → 路由器管理页（华硕的叫「网络工具 → 网络唤醒」）→ 填有线网卡的 MAC，
或任意 WOL app（**有线网卡 MAC**、子网广播地址（本网段最后一位是 255）、端口 9）。

**验收就一步**：手机点「睡眠」→ 电脑风扇停 / 灯转成呼吸 → 手机发幻数据包 →
看 80 能不能打开、模型能不能自动重载。**第一次测之前先去机器前确认能手动唤醒**，
免得睡过去叫不醒。

> 备查（走有线那条路时要做的，2026-09-14 探明）：网线插主板 I225-V 口；
> BIOS `Advanced → APM Configuration`：`ErP Ready`=Disabled、`Power On By PCI-E`=Enabled；
> **跑一次 `open-firewall.bat`** —— 现在 8090/8091 靠 Windows 弹窗自动建的 `Python`
> 程序规则，**只覆盖 Public 配置文件**，以太网插上若被判成「专用」就会被挡
> （表现是「插了网线反而连不上」）。
